## 一、目标架构

```
浏览器                        Next.js BFF                     FastAPI 后端
┌──────────┐   POST/SSE    ┌──────────────────┐   POST/SSE    ┌──────────────┐
│ 设置页    │──配置覆写────▶│ 剥离敏感字段      │──────────────▶│ QueryRequest │
│          │               │ 注入 Auth header  │   (含覆写)    │ + overrides  │
│ 工作台    │──question────▶│ 健康检查          │──GET /health─▶│ /health      │
│          │◀─response─────│                   │◀─response────│ QueryResponse│
│          │               │                   │              │ (含扩展字段)  │
└──────────┘               └──────────────────┘              └──────────────┘
```

**核心原则**：
- 后端作为唯一真实配置源（env vars 定义默认值）
- 前端支持请求级覆写（per-request override），但不替代服务端配置
- BFF 层负责鉴权注入、敏感字段过滤、SSE 流式代理
- 扩展响应字段逐步从"可选"演进为"默认启用"

## 三、Phase 1：风险消除（P0）

### 目标
消除「配置模型的用户完全无法查询」这个阻塞性问题。

### 3.1 后端：容错处理未知字段

**文件**：`app/api/models.py`

```python
# 当前（高危）：extra="forbid" → 不认识字段直接 422
class QueryRequest(BaseModel):
    model_config = ConfigDict(extra="forbid")  # ← 改这里

# 长期（建议）：
class QueryRequest(BaseModel):
    model_config = ConfigDict(extra="ignore")  # 忽略未知字段
```

> ⚠️ 注意：`extra="ignore"` 不会在 Phase 1 就支持覆写逻辑，只是不再因不认识字段而报错。实际覆写功能在 Phase 2 实现。

**文件**：`app/api/models.py`

`QueryResponse` 同样改为 `extra="ignore"`，为 Phase 3 扩展字段留余地。

### 3.2 前端：BFF 层剥离未实现字段

**文件**：`frontend/app/api/v1/text-to-sql/route.ts`

在转发请求前，从请求体中移除 `model_config` 和 `datasource_config`：

```typescript
export async function POST(request: NextRequest) {
  const body = await request.json();

  // Phase 1: 剥离后端未实现的字段（Phase 2 再启用）
  const { model_config, datasource_config, ...cleanBody } = body;

  const response = await fetch(`${BACKEND_URL}/api/v1/text-to-sql`, {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify(cleanBody),
  });
  // ...
}
```

### 3.3 验证标准
- [ ] 用户在设置页配置了模型后，提交查询不再 422
- [ ] 使用默认配置（无覆写）时，行为与当前完全一致

## 四、Phase 2：配置体系重构（P1）

### 目标
设置页的配置真正影响后端行为，实现请求级模型/数据源覆写。

### 4.1 新增后端配置 API

#### `GET /api/v1/config`

返回当前服务端默认配置（不含密钥）：

```json
{
  "datasource_id": "pagila",
  "models": {
    "simple":  { "base_url": "https://...", "model_name": "gpt-4o-mini" },
    "standard": { "base_url": "https://...", "model_name": "gpt-4o" },
    "complex":  { "base_url": "https://...", "model_name": "gpt-4o" },
    "fallback": null
  },
  "schemas": ["public"],
  "tables": ["public.actor", "public.film", "..."]
}
```

> 用途：前端设置页展示当前服务端默认值，用户基于默认值做覆写。

### 4.2 扩展 `QueryRequest` 支持覆写

**文件**：`app/api/models.py`

```python
from pydantic import BaseModel, ConfigDict, Field, StrictStr, StrictBool

class ModelOverride(BaseModel):
    model_config = ConfigDict(extra="forbid")
    base_url: str | None = None
    api_key: str | None = None   # ⚠️ 仅在 HTTPS + 受信客户端场景允许
    model_name: str | None = None

class DatasourceOverride(BaseModel):
    model_config = ConfigDict(extra="forbid")
    datasource_id: str | None = None
    host: str | None = None
    port: int | None = None
    database: str | None = None
    username: str | None = None
    password: str | None = None   # ⚠️ 同上

class QueryRequest(BaseModel):
    model_config = ConfigDict(extra="ignore")

    question: StrictStr
    datasource_id: StrictStr = "pagila"
    schemas: tuple[StrictStr, ...] = ()
    debug: StrictBool = False

    # Phase 2 新增：请求级覆写（全部可选）
    model_overrides: dict[str, ModelOverride] | None = None
    datasource_override: DatasourceOverride | None = None
```

**覆写逻辑**（在 `build_production_services` 或请求处理中）：

```
if request.model_overrides:
    provider = build_provider(
        base=env_config[route],
        override=request.model_overrides.get(route)
    )
else:
    provider = build_provider(env_config[route])
```

### 4.3 前端设置页改造

**改造点**：

1. **启动时**调用 `GET /api/v1/config` 获取服务端默认值，填充设置表单的 placeholder 和默认值
2. **模型配置**：每 tier 展示当前默认值，用户可覆写 base_url / api_key / model_name
3. **数据库配置**：展示当前数据源，用户可覆写连接信息
4. **发送请求时**：仅发送与默认值不同的字段（`model_overrides` / `datasource_override`），减少不必要的数据传输

**文件**：`frontend/components/settings/ModelConfigSection.tsx`、`DatabaseConfigSection.tsx`

### 4.4 安全设计

| 层级 | 措施 |
|------|------|
| 传输 | 全链路 HTTPS（BFF → 后端强制 HTTPS URL） |
| API Key | 仅在「用户明确填写了覆写值」时才传输，不默认传服务端的 api_key |
| 日志 | 后端不记录 `api_key` / `password` 字段到日志 |
| 审计 | 覆写请求打上 `overrides_used` 标记，便于排查 |

## 五、Phase 3：响应增强（P2）

### 目标
后端暴露工作流中间数据，让前端「参考信息」面板正常工作。

### 5.1 后端数据映射

**文件**：`app/api/response.py`

```python
def build_query_response(state: SQLTaskState) -> QueryResponse:
    base = { /* 现有字段 */ }

    # Phase 3 新增：从工作流状态提取中间数据
    if state.candidate_tables:
        base["schema_candidates"] = [
            {
                "table_name": t.name,
                "schema": t.schema,
                "fields": [...],
                "score": t.score,
                "source": t.source,
                "selected": t.object_id in selected_ids,
            }
            for t in state.candidate_tables
        ]

    if state.complexity_decision:
        base["complexity_route"] = {
            "level": state.complexity_decision.level,
            "top_k": state.complexity_decision.schema_top_k,
            "model_used": ...,  # 从 model_routing_observations 提取
            "reason": format_complexity_reason(state.complexity_decision),
        }

    if state.repair_count > 0:
        base["repair_history"] = build_repair_history(state.sql_attempts)

    return QueryResponse.model_validate(base)
```

| 扩展字段 | 数据来源 | 新需开发 |
|----------|---------|:---:|
| `schema_candidates` | `SQLTaskState.candidate_tables` + `selected_generation_field_ids` | 映射即可 |
| `complexity_route` | `SQLTaskState.complexity_decision` + `model_routing_observations` | 映射即可 |
| `repair_history` | `SQLTaskState.sql_attempts`（仅失败尝试） | 映射即可 |
| `semantic_references` | 当前不存在 RAG 命中记录 | **需新增** |

> `semantic_references` 字段需要工作流中新增 RAG 命中记录机制。如果短期不需要此功能，可先返回空数组，前端组件自动隐藏。

### 5.2 `QueryResponse` 模型更新

**文件**：`app/api/models.py`

将 `extra="forbid"` 改为 `extra="ignore"`（已在 Phase 1 完成），扩展字段作为可选字段显式声明：

```python
class QueryResponse(BaseModel):
    model_config = ConfigDict(extra="ignore", frozen=True)

    # 现有字段...
    request_id: str
    trace_id: str
    # ... etc

    # Phase 3 新增（全部可选，默认不序列化 None 值）
    schema_candidates: list[SchemaCandidate] | None = Field(default=None)
    semantic_references: list[SemanticReference] | None = Field(default=None)
    complexity_route: ComplexityRoute | None = Field(default=None)
    repair_history: list[RepairHistoryEntry] | None = Field(default=None)
```

### 5.3 前端对接

前端类型文件和组件已就绪，只需后端开始返回数据即可自动生效。唯一需要验证的是字段名和结构是否完全匹配（对照 `frontend/lib/types.ts`）。

## 六、Phase 4：安全与可观测性（P3）

### 6.1 API Key 鉴权对接

**文件**：`frontend/app/api/v1/text-to-sql/route.ts`

```typescript
const BACKEND_URL = process.env.TEXT_TO_SQL_API_URL;
const API_KEY     = process.env.TEXT_TO_SQL_API_KEY;  // Phase 4 新增

export async function POST(request: NextRequest) {
  const headers: Record<string, string> = {
    "Content-Type": "application/json",
  };

  // 如果配置了 API Key，注入 Authorization header
  if (API_KEY) {
    headers["Authorization"] = `Bearer ${API_KEY}`;
  }

  const response = await fetch(`${BACKEND_URL}/api/v1/text-to-sql`, {
    method: "POST",
    headers,
    body: JSON.stringify(cleanBody),
  });
  // ...
}
```

> API Key 来自 EdgeOne Makers 环境变量（或本地 `.env`），不暴露给浏览器端 JavaScript。

### 6.2 健康检查集成

**前端**：新增 `frontend/lib/health.ts`

```typescript
export async function checkBackendHealth(): Promise<boolean> {
  try {
    const res = await fetch("/api/v1/health", { method: "GET" });
    const data = await res.json();
    return data?.status === "healthy";
  } catch {
    return false;
  }
}
```

**BFF**：新增 `frontend/app/api/v1/health/route.ts`

```typescript
export async function GET() {
  const res = await fetch(`${BACKEND_URL}/health`);
  const data = await res.json();
  return NextResponse.json(data, { status: res.status });
}
```

**设置页**：「关于」页面增加「后端状态」指示器，展示连接状况和后端版本。

### 6.3 错误处理增强

BFF 层统一处理后端不可达、超时、鉴权失败等场景，返回标准化错误响应（前端已有对应的 ErrorCard 展示逻辑）。

## 八、兼容性与迁移

### 8.1 向后兼容

- 所有新增字段均为**可选**（`None` / `undefined` 时不参与序列化）
- 不传覆写字段时，后端行为与当前完全一致
- 前端通过可选链（`?.`）安全读取，旧版后端不返回扩展字段时 UI 自动隐藏

### 8.2 部署顺序

待部署到 EdgeOne Makers 时：

1. **先部署后端**：确保新增字段和容错处理生效
2. **再部署前端**：启用覆写传输和健康检查
3. **最后上线设置页增强**：调用 Config API 获取默认值

### 8.3 回滚方案

如果任一期部署出问题：
- 后端：移除新字段声明（`extra="ignore"` 确保不崩）
- 前端：BFF 层剥离未实现字段（Phase 1 已有），设置页可降级为纯 localStorage 模式
