# 开发交接指南

## 先读什么

1. `docs/Text-to-SQL项目复现规格.md` 的“MVP 编码入口”；
2. 当前任务对应章节；
3. 涉及测试、安全、错误或 Gold 时读 `docs/Text-to-SQL测试与验收规格.md`；
4. Pagila E2E 再读 `evaluation/cases/pagila_mvp.jsonl`。

`docs/Text-to-SQL原项目参考信息.md` 只用于历史背景，不是需求，也不得推送。

## 关键入口

| 关注点 | 文件 |
|---|---|
| 本地统一启动 | `app/cli.py`、`app/local/launcher.py` |
| FastAPI 组装与 lifespan | `app/api/application.py` |
| 生产资源创建与关闭 | `app/api/bootstrap.py` |
| Profile CRUD | `app/local/model_service.py`、`app/local/datasource_service.py` |
| 非敏感 SQLite | `app/local/profile_store.py` |
| 进程内凭据 | `app/local/credential_store.py` |

| Profile 查询解析 | `app/local/profile_resolver.py` |
| Workflow | `app/workflow/graph.py`、`app/workflow/nodes/` |
| SQL 安全 | `app/validation/sql_validator.py` |
| 前端 BFF | `frontend/app/api/v1/` |

## 开发流程

本仓库只使用 `main`。做功能或修复时先写能说明用户行为的失败测试，再做最小实现。
不要重构核心 Workflow 来完成外围交付任务。新增 Secret 字段必须证明不会进入 SQLite、
OpenAPI 响应、日志、Trace 或浏览器持久化。

常用快速验证：

```bash
PYTHONDONTWRITEBYTECODE=1 .venv/bin/pytest -q -p no:cacheprovider tests/unit tests/security
cd frontend
npm test
npm run typecheck
npm run lint
npm run build
```

PostgreSQL/Pagila 与 MySQL/Sakila 的 fixture、Compose 和命令分别见 README 以及
`infrastructure/pagila`、`infrastructure/mysql`。真实实例不可用时，不得把 skip 或
Mock 结果描述成真实环境通过。

## 提交前

- `git diff --check`；
- 检查 `git status`，不要覆盖或混入他人的未提交修改；
- 确认 origin 为 `https://github.com/lingyunjie321/text-to-sql-lite.git`；
- 不提交 `.env`、fixture 下载目录、Profile SQLite、Secret 或历史参考文档；
- 完成相关验证后直接推送 `main`，不创建额外分支或 PR。
