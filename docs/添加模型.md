# 添加模型

## 支持范围

第一版使用一个 OpenAI-compatible 生成模型，并把它映射到 simple、standard、
complex 三条内部路由。支持远程 HTTPS 服务以及本机 Ollama、vLLM、LM Studio
等回环 HTTP 服务。Embedding 完全可选；不配置时使用 BM25-only。

## 通过界面配置

启动工具后进入“设置 → 模型配置”：

1. 新建模型，填写 Profile ID、名称、API 根地址和模型名；
2. 如需 Embedding，同时填写地址、模型名和维数；三个字段必须全有或全无；
3. 点击测试；生成模型必须成功，Embedding 失败时界面会说明仍可使用 BM25-only；
4. 保存并设为当前模型。

远程地址必须使用 HTTPS。本机 `localhost`、`127.0.0.1` 或 IPv6 loopback 可使用
HTTP。地址不能包含用户名、密码、query 或 fragment。API 根地址通常以 `/v1`
结尾，后端会追加 `/chat/completions` 或 `/embeddings`。

## 凭据语义

API Key 只随测试、创建或更新请求进入后端进程内存，不写入 SQLite、响应、Trace、
历史或 localStorage。编辑时不填写 Key 表示保留当前内存值；显式清除表示删除。
无鉴权的本地服务可以不填写 Key。应用重启后需要重新输入。

## API 示例

```bash
curl --request POST http://127.0.0.1:8000/api/v1/local/models/test \
  --header 'Content-Type: application/json' \
  --data '{
    "provider_type":"openai_compatible",
    "base_url":"http://127.0.0.1:11434/v1",
    "model_name":"qwen3:8b"
  }'
```

测试成功后创建 Profile：

```bash
curl --request POST http://127.0.0.1:8000/api/v1/local/models \
  --header 'Content-Type: application/json' \
  --data '{
    "id":"local-model",
    "name":"本地模型",
    "provider_type":"openai_compatible",
    "base_url":"http://127.0.0.1:11434/v1",
    "model_name":"qwen3:8b"
  }'
```

如启用了 `TEXT_TO_SQL_API_KEY`，为以上请求增加
`Authorization: Bearer <本地配置的值>`，不要把真实 Key 写入脚本或仓库。
