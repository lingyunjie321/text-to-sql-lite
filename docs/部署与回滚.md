# 部署与回滚

> 本文描述 Text-to-SQL Agent 后端的容器化部署、升级与回滚操作。
> 适用范围：单机容器部署。更大规模的编排（K8s 等）可复用同一镜像与环境契约。

## 1. 组件与依赖

| 组件 | 说明 | 必需性 |
|---|---|---|
| 后端容器 | 本仓库根 `Dockerfile` 构建，暴露 8000 端口 | 必需 |
| PostgreSQL + Pagila | `infrastructure/pagila/compose.yaml`，镜像 sha256 锁定 | 必需 |
| LLM 服务 | OpenAI-compatible Chat Completions 端点 | 必需 |
| Embedding 服务 | OpenAI-compatible Embeddings 端点 | 必需 |
| 前端 | `frontend/`（Next.js），独立部署，经 BFF 代理到后端 | 可选 |

## 2. 环境变量契约

后端通过环境变量注入配置（见 `.env.example`）。关键项：

| 变量 | 说明 |
|---|---|
| `TEXT_TO_SQL_DATABASE_DSN` | **只读账号** DSN，禁止给写权限账号 |
| `TEXT_TO_SQL_LLM_BASE_URL` / `TEXT_TO_SQL_LLM_API_KEY` / `TEXT_TO_SQL_LLM_MODEL_NAME` | 生成模型 |
| `TEXT_TO_SQL_EMBEDDING_*` | Embedding 服务 |
| `TEXT_TO_SQL_ALLOW_ADHOC_DATASOURCES` | 是否允许请求级内联数据源，**生产必须保持 `false`** |

安全基线：
- 数据库账号必须为只读角色（`default_transaction_read_only = on`，仅 SELECT 授权）。
- Secret 只经环境变量/密钥管理注入，不写入镜像、不进日志。
- 容器以非 root（uid 10001）运行。

## 3. 构建与启动

```bash
# 构建镜像（构建上下文必须是仓库根目录）
docker build -t text-to-sql-agent:<版本或提交短SHA> .

# 启动 Pagila（如尚未运行）
docker compose -f infrastructure/pagila/compose.yaml --env-file .env up -d --wait

# 启动后端
docker run -d --name text-to-sql-agent \
  --env-file .env \
  -p 8000:8000 \
  text-to-sql-agent:<版本或提交短SHA>

# 验证
curl -s http://127.0.0.1:8000/health
```

镜像必须打**不可变标签**（版本号或提交短 SHA），禁止只用 `latest`。

## 4. 升级流程

1. 在预发/本地用目标版本镜像跑 `tests/unit tests/security`（CI 已覆盖时可跳过）。
2. 构建并推送新镜像，标签为新版本。
3. 启动新容器（新名字或先停旧容器），确认 `/health` 返回 healthy。
4. 冒烟：`POST /api/v1/text-to-sql` 发送一个简单问题，确认返回成功。
5. 观察 10–30 分钟日志（错误率、延迟）。
6. 任一失败 → 立即执行回滚（第 5 节）。

注意：若版本涉及 Stage 冻结项（受控代码、配置、语义 manifest），
升级前必须确认对应冻结已重建，否则评测与基线校验会按设计失败。

## 5. 回滚预案

回滚单位是**镜像标签**，回滚 = 用上一个已知良好镜像重新启动容器：

```bash
docker stop text-to-sql-agent && docker rm text-to-sql-agent
docker run -d --name text-to-sql-agent \
  --env-file .env \
  -p 8000:8000 \
  text-to-sql-agent:<上一个良好标签>
curl -s http://127.0.0.1:8000/health
```

要求与验证：
- 保留最近 3 个已知良好镜像标签记录（建议记入发布日志）。
- 回滚后必须重新做第 4.4 步冒烟。
- 数据库 Schema 当前由锁定 fixture 决定，应用不做迁移写操作，
  因此无"数据库回滚"步骤；若未来引入迁移，必须先备份
  （`pg_dump`）再升级，并在本节补充恢复步骤。
- 配置回滚：`.env` 变更应同步记录，回滚配置 = 还原上一版 `.env` 并重启。

## 6. 数据保留与清理

- 集成测试/验证使用的临时数据库角色（`codex_*` 前缀）用后必须删除并
  确认残留为 0。
- Pagila 命名卷 `pagila-data` 含快照数据，删除前确认不再需要：
  `docker compose -f infrastructure/pagila/compose.yaml down -v`。
