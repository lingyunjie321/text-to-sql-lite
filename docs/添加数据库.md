# 添加数据库

## 安全前提

正式支持 PostgreSQL 与 MySQL。请先创建只读数据库账号；AST 安全校验和只读事务
不能替代账号权限。DatasourceProfile 保存主机、端口、数据库、用户名和 allowlist，
密码只保存在后端进程内存中。

当前数据库设置页尚未接入正式 Profile API，并且旧表单可能写入 localStorage。
不要在该页面填写真实密码。请使用后端 OpenAPI
`http://127.0.0.1:8000/docs` 或以下 API。

## 1. 测试连接并发现结构

先将密码读入临时 shell 变量。这样密码原文不会进入命令参数或 shell 历史；请求完成后
立即清除变量。

```bash
read -r -s "DB_PASSWORD?数据库密码: "
printf '\n'
curl --request POST http://127.0.0.1:8000/api/v1/local/datasources/test \
  --header 'Content-Type: application/json' \
  --data-binary @- <<JSON
{
    "database_type":"postgresql",
    "host":"127.0.0.1",
    "port":5432,
    "database":"analytics",
    "username":"text_to_sql_reader",
    "password":"$DB_PASSWORD"
}
JSON
unset DB_PASSWORD
```

响应列出非系统 Schema 和表/视图。该发现范围不等于 AI 权限。

## 2. 保存最小 allowlist

只选择完成任务所需的表；表名必须是 `schema.table`，并且 Schema 必须同时出现在
`allowed_schemas` 中。

```bash
read -r -s "DB_PASSWORD?数据库密码: "
printf '\n'
curl --request POST http://127.0.0.1:8000/api/v1/local/datasources \
  --header 'Content-Type: application/json' \
  --data-binary @- <<JSON
{
    "id":"local-postgres",
    "name":"本地分析库",
    "database_type":"postgresql",
    "host":"127.0.0.1",
    "port":5432,
    "database":"analytics",
    "username":"text_to_sql_reader",
    "allowed_schemas":["public"],
    "allowed_tables":["public.orders","public.customers"],
    "password":"$DB_PASSWORD"
}
JSON
unset DB_PASSWORD
```

创建和更新会在线验证 allowlist；不存在或账号不可见的对象不会保存。随后可读取完整
字段、主键与外键：

```bash
curl http://127.0.0.1:8000/api/v1/local/datasources/local-postgres/metadata
```

## 3. 使用两个 Profile ID 查询

```bash
curl --request POST http://127.0.0.1:8000/api/v1/text-to-sql \
  --header 'Content-Type: application/json' \
  --data '{
    "question":"按月统计订单金额",
    "datasource_id":"local-postgres",
    "model_profile_id":"local-model"
  }'
```

Profile 缺失返回 404；重启后凭据缺失或 allowlist 无效返回 409；连接不可用返回
503。系统不会悄悄回退到 `.env` 数据源。
