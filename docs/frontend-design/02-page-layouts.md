## 1. 首页 / 查询工作台

### 1.1 页面目标

提供自然语言查询输入和结果展示的对话式工作台。用户在此提问、查看结果、回应澄清、处理错误，完成完整的数据查询闭环。

### 1.4 用户操作主流程

```
步骤 1: 用户进入首页，看到欢迎区 + 示例问题
         │
         ├─ [路径 A] 点击示例问题 Chip
         │    → 自动填入输入框并提交
         │
         ├─ [路径 B] 手动输入问题
         │    → 在底部 Textarea 输入问题
         │    → 点击提交按钮（或按 Enter）
         │
         ▼
步骤 2: 系统显示加载骨架屏
         → 用户消息气泡出现在对话流
         → 下方出现加载卡片（Spinner + "正在理解你的问题..."）
         → 输入框禁用，提交按钮变为加载态
         │
         ▼
步骤 3: 收到后端响应，按 status 分支
         │
         ├─ SUCCEEDED_FIRST_PASS / SUCCEEDED_REPAIRED
         │    → 加载卡片替换为结果卡片
         │    → 状态标签：绿色 "查询成功"
         │    → 展示结果表格（默认视图）
         │    → SQL 折叠区出现（默认折叠）
         │    → 元信息折叠区出现（默认折叠）
         │    → 输入框重新可用
         │
         ├─ CLARIFICATION_REQUIRED
         │    → 加载卡片替换为澄清卡片
         │    → 展示澄清问题（clarification.question）
         │    → 出现补充输入框 + 提交按钮
         │    → 用户补充后重新提交（带上原始问题 + 补充信息）
         │
         ├─ 各种 FAILED_*
         │    → 加载卡片替换为错误卡片
         │    → 展示友好错误文案
         │    → 可重试的错误显示"重试"按钮
         │    → 不可重试的错误显示"修改问题"提示
         │
         ▼
步骤 4: 用户继续提问（回到步骤 2）
         → 新的对话轮次追加到对话流
         → 历史记录自动保存到 localStorage
```

#### 1.5.4 成功状态（SUCCEEDED_REPAIRED）

与 `SUCCEEDED_FIRST_PASS` 基本一致，区别：

- 状态标签文案："经修复后成功"
- 标签颜色：蓝色（而非绿色）`bg-blue-50 text-blue-700`
- 元信息区展开后显示 `repair_count`（如 "经 2 次修复后成功"）
- 弱化展示：不弹 Toast，不额外高亮，仅在状态标签和元信息中体现


**各错误类型的友好文案与重试策略**：

| status | error_type | 友好文案 | 是否可重试 | 按钮文案 |
|--------|-----------|----------|-----------|----------|
| `REJECTED_SECURITY` | `PERMISSION_DENIED` | 该查询因安全策略被拒绝，请尝试调整问题的范围或表述。 | ❌ 不可重试 | "修改问题"（聚焦输入框） |
| `FAILED_TIMEOUT` | `TIMEOUT` | 查询超时，数据库可能正在处理大量数据。请尝试缩小查询范围后重试。 | ✅ 可重试 | "重试" |
| `FAILED_CONNECTION` | `CONNECTION_ERROR` | 无法连接到数据库，请稍后重试。 | ✅ 可重试 | "重试" |
| `FAILED_RESOURCE_RISK` | `RESOURCE_RISK` | 查询可能消耗过多资源，请尝试缩小范围（如增加时间范围限制、减少关联表）。 | ❌ 建议修改 | "修改问题" |
| `FAILED_DUPLICATE_LOOP` | `DUPLICATE_SQL` | 系统多次生成了相同的 SQL 但未能成功执行，请尝试换一种方式描述你的问题。 | ❌ 建议修改 | "修改问题" |
| `FAILED_REPAIR_EXHAUSTED` | `SYNTAX_ERROR` / `SCHEMA_ERROR` / `DIALECT_ERROR` | 系统尝试修复 SQL 但未能成功，请尝试更清晰地描述你的问题。 | ❌ 建议修改 | "修改问题" |
| `FAILED_INTERNAL` | `UNKNOWN` 等 | 系统遇到内部错误，请稍后重试。 | ✅ 可重试 | "重试" |

- 状态标签：红色 `bg-red-50 text-red-700`
- 错误图标：`AlertCircle`（lucide-react）
- 错误文案：友好脱敏文案（不直接展示后端 `error.message`，而是根据 status 映射）
- 元信息折叠区：展示 `error.error_type` 和 `error.code`（供技术排查）

- 桌面端：输入区内嵌在对话流底部
- 移动端：输入区 `fixed bottom-0`，主内容区增加 `pb-32`

- 截断提示：`truncated=true` 时表格上方显示 "⚠ 实际结果超过 1000 行，已截断展示前 1000 行"
- 空结果：`returned_row_count=0` 且 `columns` 非空时，显示 "查询成功，但没有匹配的数据"
